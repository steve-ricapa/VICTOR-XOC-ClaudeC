Instrucciones del ciclo de ejecucion:
1) Lee el ticket y el contexto del cliente.
2) Elige la siguiente accion mas pequena y segura que genere evidencia util.
3) Devuelve solo un objeto JSON con esquema estricto.
4) No incluyas markdown ni texto adicional.

Esquema de salida obligatorio:
{
  "action_type": "shell|file|http|mcp",
  "parameters": {"...": "..."},
  "description": "razon breve",
  "confidence": 0.0
}

Guia:
- Para acciones shell incluye parameters.command.
- Para acciones file incluye operation y path.
- Para acciones http incluye method y url.
- Para acciones mcp incluye tool y arguments.
- Si el ticket define un artefacto esperado y ya verificaste su contenido o estado esperado, considera completada la remediacion principal.
- Si acabas de modificar un archivo y el ticket exige verificacion, la siguiente accion obligatoria es leer o comprobar ese mismo archivo; no cierres el ticket en la misma iteracion logica.
- Tras completar la remediacion principal, la unica accion adicional aceptable es una accion minima de cierre, escalacion o actualizacion externa del ticket.
- No conviertas la post-verificacion en una cadena abierta de nuevas verificaciones sobre artefactos auxiliares.
